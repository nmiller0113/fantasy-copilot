# Waiver night

Read this on waiver eve before the first claim is filed in any league, and again at the
flip. Skill section 8 holds the cadence and the tests that price an add (the free-claim
bullet, the replaceability test, the burn-the-claim test); this page holds the night itself:
the order of work, the IR slots, when a claim must be filed, how a drop is argued, the flip,
and what a reviewer is given.

## The order of the night

The league-wide news sweep (`references/lineups.md`) is required before the waiver pass: it
opens each week's work, waiver eve at the latest, and is redone first when the last one is
more than about two days old. Every player in a claim or a drop, an IR-slot fix's drop
included, is read against it, and each claim and drop names the item it rests on, or says that
no item bears on it. The pass also saves both services' projections for every rostered player
at the same moment, for the accuracy record (`references/lineups.md`, which service to lean
on).

The work runs in this order across every league, once the IR slots are clean (below), since
an ineligible occupant blocks every add: every contested claim in every league first, since
each must be filed before the flip (claim timing, below); then the free adds at the flip;
housekeeping last, which is the empty starting slots the waiver-run window names and the
lineup only where the user asks for it.

The delivery is waiver moves only, one league per message, and the next league comes only on
the user's word: any IR-slot fix with its drop; the claims in filing order, each with its drop
and the fallback if it loses; the free adds at the flip. The rounds follow the order above,
every league's claims before the flip and every league's free adds at it. Lineups, pivots and
bench verdicts belong to the lineup pass (`references/lineups.md`) and stay out of the
delivery unless the user asks.

## Before filing: the IR slots

On the host where this was verified, a player in an IR slot whose tag no longer qualifies for
it (a tag that moved from out to doubtful or questionable) blocks every transaction that adds
a player until he is moved out of the slot. The host's help page on IR eligibility lists the
tags that qualify; read it once per host and record it in the private document (skill section
9). So every league's IR slots are read from the host's own team page before waiver night,
each occupant's tag against that list, and every ineligible occupant is moved out before the
first claim is filed in that league. The move needs an open bench spot, so on a full roster
it costs a drop, argued like any other (the holds, below) and named in the same line.

The same occupant has also been seen to block the user from building a trade proposal on
that host, so a trade from the user's roster waits on the same fix. Whether the drop that
opens the spot is a gamble depends on the rest of the week. Where a claim or an add is also
wanted in that league in the same window, the drop is owed anyway and is no bet on the trade:
said so. Where nothing else is wanted, the drop pays off only if the trade is accepted, which
is the user's call to make, said as exactly that, with the option of sending nothing until the
slot is fixed for another reason. Either way the body named is the one the roster loses least
in BOTH outcomes, the trade accepted and the trade refused, each lineup said in the same line.

## Claim timing: priority works only before the flip

Where the host flips unclaimed players to free agency when the waiver period ends, ahead of
the run that settles the claims (verified on one host at midnight on the night of the run;
each league's flip time is recorded once in the private document), the flip splits the pool.
Every player nobody has claimed becomes a free agent, first come. A player who already
carries a claim stays on waivers until the run, and the host accepts no new claim on him from
anyone; that host's refusal reads "You cannot submit a new waiver claim for this player until
outstanding claims by other managers have been processed". So priority buys a player only
before the flip:

- **Every contested target is a claim filed before the flip**, never "a free add at the flip
  if he is still there": a rival's claim keeps him off the flip, and after it the user cannot
  bid at all. Contested means real demand: a high or rising percent rostered, a name the
  market is adding (the transaction watch's added-in-two-or-more-leagues list, the host's
  transaction trends), or a rival whose roster has the need (the manager digest).
- **The flip is for uncontested players only.** Nobody else is expected to claim him, so the
  free add at the flip costs no priority.
- **A contested player who does not earn the claim is not a target**: he is passed, and said
  as passed. Whether he earns it is skill section 8's call: the replaceability test, and for a stash the
  burn-the-claim test of `references/ir-stash.md`; while the user holds last priority every
  claim is free (the free-claim bullet).
- **Never spend waiver priority on a kicker or a team defense**: both are free adds at the
  flip, or once they clear on a host with none, and neither is worth priority that has value.
  While the user holds last priority a claim is free and holds him off the flip (the
  free-claim bullet), so one may be filed there, a drop named.

## The drops: a hold is not a veto

A hold is a player the user deliberately keeps: a ceiling stash, a kept handcuff, a trade
chip, a move the user declined. Each is written to the private document (skill section 9),
per league, when the user makes it: the player, the decision, its date, the user's own words,
and its exit test, the event that would end it. Every drop is checked against that list
before the user sees it.

- **Projections alone never justify cutting a held player**, since projections do not price
  the ceiling the hold is for: a stash's rest-of-season number prices the starter ahead of
  him staying healthy (`references/ir-stash.md`, order by ceiling).
- **A call to cut him argues against the hold's own thesis, or cites a fact newer than the
  hold.** Against the thesis means ceiling against ceiling: for example, the stash cannot
  start over the rostered starter at his position, so his ceiling pays only if that starter
  breaks, while the add's ceiling is a starting job at a scarcer position. A newer fact is one
  the hold did not have: its exit test met, a new designation, a role change that passes the
  trend test below.
- **A hold is never untouchable either.** The argument is made out loud, both services'
  numbers in the line (`references/lineups.md`, saying the number), and the user decides.

## Every add is priced as the week AND the asset

An add is used twice: in the lineup the week it is made, and afterwards as a held player who
covers the next injury or bye or becomes a trade chip. So every claim and every add of a
position player, a one-week fill included (a bye cover, an injury fill), is priced on both. A
kicker or team-defense stream is the exception: it keeps the week-only two-number test of
`references/lineups.md`, since neither is held as a trade chip.

- **Both horizons on both services**, in the line that offers him: the host's and the
  engine's projection for the week AND for the rest of the season (`references/lineups.md`,
  saying the number). A comparison made on the week alone is never the comparison, however
  short the need.
- **His production**: season points per game and the last few weeks' per game from the host's
  game log, games played named (one big week is not a trend, below).
- **His market**: the host's percent rostered, the plainest read of what he fetches in a trade
  later.

These are inputs to skill section 8's replaceability test, said beside it, never a verdict
ahead of it: between two candidates who tie on the week, the rest of season and the market
are named as the tie's likely breaker, the test says which of the two can be re-acquired
later, and the user decides. The drop side is priced the same way.

## One week is not a trend

Numbers come before narrative here as on game day (`references/lineups.md`, the game-day
pass): no claim and no drop is said before the weekly lines and both engines are read, and a
news line or an article never goes first. The sweep (the order of the night, above) is
collected first and read beside those numbers, never ahead of them, and no single item decides
a claim or a drop.

Before a role change or a takeover is called, the spike is put beside BOTH players'
week-by-week lines for the season and beside both engines' numbers as they stand after the
spike. A takeover needs one of three: a trend over several weeks, a snap or route share shift
over more than one game, or a coach's statement (skill section 10's role hierarchy). A
backfield, or any pair in one position room, is judged as a pair: the incumbent's
week-over-week consistency first, then whether the spike repeats. One game swung by one
event, a fumble or a game script, is a sample of one.

An add's value includes what he does to a rostered teammate: the threat he poses to that
teammate's work, and the hedge that owning him buys against it. The hedge is worth buying
only when the threat is real under this test.

## The waiver-run window

Where the host flips unclaimed players to free agency at the moment the waiver period
ends, ahead of the run that settles the claims, that gap is its own pass and not the
tail of the claim pass. Two readings are taken in it, both of every league and neither
of a subset.

The arrival date `scripts/transactions.py` prints (`references/transaction-watch.md`) does
not move, since the flip and the run fall on the same morning; this section orders the two
within it: skill section 8's "a claim until that waiver period ends" is this flip where the
host has one, and the run where it has none, for a player nobody has claimed. One who carries
a claim stays on waivers until the run either way (claim timing, above).

**The pool is re-read for every league at the flip, however settled a league looked
before it.** A pool read even an hour earlier is stale: the flip moves every
unclaimed player off waivers into the free-agent pool at once, so the best player at a
position can enter a league's pool at that moment and, with every manager's adds landing
in the same minutes, be gone minutes later. Skipping the leagues whose first choice was already
taken, and re-reading only the rest, misses that arrival in the leagues that were
skipped. The read asks the host for free agents only, never the availability filter that
also returns players still on waivers, since those cannot be added now and reading them as
available is how a name gets recommended that the user cannot click.

**The team's own pending block is read before any add or drop is named in that league.**
A player already committed as the drop on a filed claim cannot be dropped a second time,
so naming him is an error the user discovers only as a refusal at the host. The block is
read from the host's team page in the same pass as the pool, and every player it holds
as a drop is treated as unavailable until the run resolves, unless the claim holding him
is named for cancellation in the same line, which is the user's click. This applies most sharply to
the assistant's own claims from earlier the same evening: a roster the assistant changed
itself is still state to be re-read, not state it can recall.

Where one league's room has repeatedly moved faster than the others, that league is
worked first in the window rather than in list order, and which league that is belongs
in the private document beside the manager who makes it true.

The same pass, its adds made, names every starting slot the host shows empty. A claimed or
added kicker or defense arrives on the bench, and a slot left empty scores nothing, which costs more
across a portfolio than any single add in the window gains. `references/lineups.md` holds
what then goes in each slot, and its "Saying the number" governs every comparison this pass
offers, the pool's board as much as the lineup's. The engine's raw projection for each pool
name is the one the waiver-eve Finder read already holds, since the flip moves availability
and not projections, unless the engine's news feed shows an item on him since that read, in which case his
Finder number is re-read;
the host's number is this pass's own.

## A reviewer pass

Any independent reviewer pass on waiver or lineup calls (a subagent, a fresh-context review)
gets in its prompt the user's holds for every league in scope, each with its player,
decision, date, the user's words and its exit test, and every ruling the user has made in the
current session, verbatim, never summarized: a reviewer who never saw a hold cuts it on
projections. Before any drop reaches the user, the reviewer's or the copilot's own, the
copilot checks it against that list itself.
